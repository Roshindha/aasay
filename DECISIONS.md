## Additional decisions

- **F1 Forbidden name.** `PLAN.md` (the user-supplied spec) contains the former name and the plan's layout used a directory name derived from it. The detector modules live in `src/lanes/` instead of the directory name the plan's layout used. `PLAN.md` itself is the only file excluded from the forbidden-name check; it is left unedited because it is the user's spec.
- **F2 Versions.** Pinned `typescript@5` (not 7), `eslint@9`, `vitest@3` for compatibility with `eslint-config-next@16`; `@types/node@22`. `diff@8`.
- **F3 Registry 404 semantics.** A 404 for a scoped package, or any lookup when a custom registry is configured (`.npmrc` registry / `.npmrc` scope registry, `pip.conf`/`--index-url`/`[[tool.poetry.source]]`), is `likely`, not `confirmed`.
- **F4 Patch application.** Gate uses `git apply` in a temp dir (fallback `patch -p1`); diffs are generated with the `diff` package.
- **F5 Tests of MCP.** The stdio test spawns the server through `tsx` and talks to it with the SDK client.
- **F6 Local Python modules.** Any file stem or directory name inside the scanned repo counts as a local module (covers sibling and src-layout imports); this can mask a third-party import that shares a name with a repo directory.
- **F7 (superseded by F26) OpenAI host.** An opt-in OpenAI client pinned to `api.openai.com` was originally added as an exception to the host allowlist. It has been removed; see F26.
- **F8 Lane naming.** Detector lanes live in `src/lanes/`; the heuristic lanes are deterministic and the LLM adds only `speculative` findings.
- **F9 Seeded benchmark.** 11 planted bugs (3 hallucination, 3 spec-drift, 3 test-theater, 2 phantom-dependency) in `fixtures/seeded-demo`; the detectors were written alongside the fixture so the 100% score shows plumbing works, not real-world accuracy. Line tolerance 1. Gate: recall >= 0.8, precision >= 0.8, critical recall = 1.0.
- **F10 Non-planted deps behaviour.** Typosquat and transitive-only detection are implemented and unit-tested but intentionally not planted in the seeded demo (the plan specifies exactly two planted phantom bugs).
- **F11 Gate checks.** With no install step available in the temp dir, built-in checks are: `git apply --check` + apply, JSON validity for patched `.json`, and `ast.parse` for patched `.py` (skipped if `python3` is absent). Callers may add `checks` (used by the secrets test). A candidate is eligible only if it applies and every check passes. Check subprocesses get an allowlisted env (`PATH LANG LC_ALL TERM TZ SHELL` + `HOME`=temp dir, `CI=1`), and any name matching `KEY|TOKEN|SECRET|PASSWORD|PASSWD|CREDENTIAL|AUTH|COOKIE|SESSION` is dropped even if explicitly provided.
- **F12 Scoring.** Five axes in [0,1], weighted correctness .40, safety .20, minimality .15, maintainability .15, testability .10. Correctness is measured, not guessed: the full review is re-run on the patched tree (finding must disappear; −0.3 per new medium+ finding; −0.45 for dangling references to removed imports). Non-applying/failed-check candidates are ineligible and score 0.
- **F13 Patch coverage.** Generators exist for: phantom deps (remove / replace / replace+declare / declare / comment-out), missing exports (alias / rename), invented APIs (replace), constant drift (set to spec), tautological assertions (delete / failing TODO). Signature drift and no-assertion tests intentionally get no auto-patch (need human judgement). Replacement names for phantom packages come from a small hand-curated table (`src/patches/replacements.ts`) plus the typosquat target; the semantic fit of a replacement is not verified.
- **F14 UI.** One-page dashboard (`src/app/dashboard.tsx`) over route handlers `/api/seeded`, `/api/live`, `/api/tournament`. Recall/precision/gate are shown only for the seeded run; live scans show counts only (no answer key). A shared service layer (`src/core/service.ts`) keeps an in-memory store of recent scans, used by both the UI and MCP. `turbopack.root` set in `next.config.mjs` to silence the parent-lockfile warning. The build prints a benign "dynamic filesystem access" tracing warning for the fixtures reader; the app is local-only.
- **F15 GitHub fetch.** PR scans fetch changed reviewable files plus all manifests/specs from the PR head tree (for context); repo scans fetch manifests plus code up to 80 files / 150 KB each. Only `api.github.com` is contacted; `GITHUB_TOKEN` is sent only there.
- **F16 MCP.** `src/mcp/server.ts` (name `assay`, stdio). Tools: assay_review, assay_fix, assay_score_patch, assay_handoff, assay_eval, assay_check_deps. Resources: `assay://findings`, `assay://evidence-graph` (latest scan), `assay://answer-key`. Prompts: `review`, `fix_handoff`. Scans are kept in process memory and addressed by `scanId`. `source=path` reads a local directory the client names (local trust model, capped at 300 files / 200 KB each). The stdio test spawns the server via `tsx` with `ASSAY_OFFLINE=1`.
- **F17 refresh-popular.** npm refreshes via the registry search endpoint (popularity-ranked, allowed host). PyPI has no ranking endpoint on an allowed host, so `--pypi-file` takes a locally downloaded ranking; the script never invents names. Not run in this build (no refresh was needed; fixtures are the hand-curated snapshots).

## UI polish (separate pass; UI layer only)

- **F18 No new runtime dependencies.** Everything is Tailwind + inline SVG icons + system fonts; no icon/font/CDN assets. New *dev* dependencies only: `@playwright/test` (smoke + screenshots), `@axe-core/playwright` (WCAG 2.1 A/AA scans in both themes), `@testing-library/{react,jest-dom,user-event}`, `jsdom`, `@vitejs/plugin-react` (Vitest JSX). Pins: `jsdom@26` (jsdom 31 needs Node ≥ 24.15; this machine has 24.7) and `@testing-library/jest-dom@6` (v8 needs Vitest 5; we use 3).
- **F19 Config touched outside `src/app`.** `vitest.config.ts` (also include `*.tsx`, React plugin; UI tests opt into jsdom via a docblock so the logic tests still run in node), `tsconfig.json` (include `e2e/` and `.tsx` tests), `playwright.config.ts`, `package.json` scripts (`e2e`, `screenshots`). No logic module, fixture or MCP file changed.
- **F20 Visual direction.** Neutral dark theme by default with a light theme; first load follows `prefers-color-scheme`, a toggle persists the choice (inline pre-paint script, so no flash). Colour roles: *confirmed* = red accent, *likely* = amber accent, *speculative* = muted grey. Severity is never shown by hue (4-step meter + text), so labels own the accents. Label and severity always have an icon/shape plus text. Contrast is unit-tested from the CSS tokens (`tests/ui-contrast.test.ts`) and scanned with axe in the browser.
- **F21 Navigation.** Hash routes (`#/verdicts`, …) so views are deep-linkable. Nav has three groups (Run / Analyze / Fix). "Context budget" is both a compact panel (Seeded view) and its own nav entry. A top-bar Seeded/Live switch chooses which scan the Analyze/Fix views show; running a live scan switches to it. This replaces the old Seeded/Live toggle + tab strip; behaviour of the seeded run, live scan and tournament API calls is unchanged.
- **F22 Offline/online indicator is derived, not reported.** The UI shows "Offline · recorded fixtures" for the seeded source (always true), "Online · GitHub, npm, PyPI" once a live scan exists, and "Browser offline" from `navigator.onLine`. The server does not expose whether `ASSAY_OFFLINE=1` was applied to a live scan, so a live scan run with that variable would still be labelled online. Fixing this needs an API field (a logic change), so it was left alone.
- **F23 Error scrubbing.** `ErrorState` redacts token-like strings (`ghp_…`, `github_pat_…`, `sk-…`, `Bearer …`, `?access_token=…`) before display, in addition to the server never including tokens.
- **F24 Graph.** Nodes carry visible kind words and an accessible name equal to their visible text (axe `label-content-name-mismatch`); full labels are shown in the inspector rather than as SVG tooltips. Under 768px the graph is replaced by a grouped list; on desktop a Graph/List toggle is available.

## Finishing pass

- **F25 `offline` is reported by the API.** Every scan carries `offline: boolean` (seeded route, live route, MCP `assay_review`/`assay_check_deps`). It is `true` when `ASSAY_OFFLINE=1`, when the offline option was used, or when no registry lookup actually went to the network (all answers from recorded fixtures, the popular snapshot, or the disk cache). It is `false` only if at least one registry request left the machine (`RegistryClient.networkCalls > 0`). It describes *registry* lookups only: a GitHub scan still fetches from `api.github.com`, which is why the badge reads "Offline · registry from fixtures/cache" rather than "Offline" for live scans. The badge uses this field; the earlier inference (F22) is superseded.
- **F26 The allowlist is absolute; OpenAI removed.** `OpenAiLlmClient`, the `openai` dependency (package.json, lockfile, `next.config.mjs`), `ASSAY_LLM`, `OPENAI_API_KEY` and `ASSAY_MODEL` handling, and the related README/`.env.example` entries are gone. `HeuristicLlmClient` is the only `LlmClient`. The only outbound hosts are `api.github.com`, `registry.npmjs.org` and `pypi.org`. If a model-backed reviewer is added later it should be a separate module with its own explicit allowlist entry, its own tests, and a documented opt-in, rather than a carve-out in the data allowlist. Remaining textual matches for "openai" in the repo are: the package *name* in the popular-package snapshots, this file, one regression test (`tests/llm.test.ts`) that sets those variables to prove they are ignored, and the user-supplied `PLAN.md`.
- **F27 Dependencies on mobile.** Under 768px (`md`) the issues table is replaced by stacked cards (package, registry, status as icon + text, verdict, location); at ≥768px the table is shown and the cards are hidden. Both are in the DOM; CSS picks one.
- **F28 Graph node labels.** Nodes now show the full label wrapped to at most two lines (per-column widths: findings 300, files 190, dependencies 250, manifests 170); only text beyond two lines is truncated, with an ellipsis. The kind tag moved out of the node (column headers show it; the accessible name still starts with the kind). Full text is always in the inspector and in the node's accessible name. Hover tooltips stay removed. Supersedes the node-label part of F24.
- **F29 Offline verification.** I did not toggle Wi-Fi: that is a system-settings change and would also cut the working session. Instead the full suite ran inside a macOS `sandbox-exec` profile that denies all outbound connections except loopback (profile below), and a test-side guard (`tests/no-network.ts`) replaces global `fetch` in every Vitest file, records any attempt, and fails the test that made it (the registry client turns network errors into "unknown", which could otherwise hide a live call). Result with the network blocked (a control `curl https://pypi.org` failed with "Couldn't connect"): `pnpm test` 185/185, `pnpm build` OK, `pnpm eval` 100% recall / 100% precision / critical recall 100% / gate PASS, `pnpm e2e` 8/8 (loopback only). No test needed to be changed to use mocks; none attempted a real request.

  ```
  (version 1)
  (allow default)
  (deny network-outbound (remote ip "*:*"))
  (allow network-outbound (remote ip "localhost:*"))
  ```
  Run as: `NEXT_TELEMETRY_DISABLED=1 sandbox-exec -f nonet.sb pnpm test` (likewise `build`, `eval`, `e2e`).

## Authorship & Disclosure Audit

- **F30 Signals, not verdicts.** The authorship audit (`src/authorship/`) reports signals with a strength (strong / moderate / speculative), evidence, a plain-language explanation and, for weak ones, a caveat. No output says who or what wrote the code; tests scan summaries and explanations for verdict phrasing. A clean result is always described as "not evidence the code was written by a person".
- **F31 Overall result.** `clear` / `needs-review` / `action-needed`. `undisclosed` and `mismatch` → action-needed. `disclosed` → clear, or needs-review when README statements conflict or a detected tool is not named in the docs. `none-found` → needs-review only on moderate *non-claim* evidence (e.g. a burst of large commits); speculative signals never change the result, and an unverifiable "hand-written" claim is not evidence.
- **F32 Disclosure edge cases.** The four statuses follow the brief. Two cases the brief leaves open: (a) a README that says AI tools were used but no strong signal exists is accepted as `disclosed` (it is the owner's own account and nothing contradicts it); (b) a README that claims "hand-written" with no strong signals stays `none-found`, with the claim listed as a moderate signal that cannot be verified. If a README contains both an AI-use and a human-only statement, status follows the AI statement and the report flags the conflict (needs-review).
- **F33 What counts as an AI signal.** Dependency/CI bots (dependabot, renovate, github-actions, …) and human co-authors are never reported. README/docs statements are read from prose only: fenced code, inline code, HTML comments and blockquotes are ignored, so documentation *about* these phrases is not read as a claim. Negated phrases ("not built with AI") count as human-only claims.
- **F34 History patterns.** A burst (≥5 commits of ≥300 changed lines within 30 minutes) is moderate; a huge initial commit (≥1500 added lines and ≥60% of all additions) and uniform structured messages (≥8 commits, ≥80% conventional subject + bulleted body) are speculative. All carry the history caveat. They need commit stats; without stats (e.g. a live scan that did not fetch them) only the message pattern can fire.
- **F35 Disclosure helper.** `draftDisclosure` builds a "How this was built" section where every factual sentence has a recorded basis (signal ids, or `owner` for text the owner supplied and which is labelled "declared by you"). Speculative signals are never used. It always includes fill-in-the-blank sections for the owner's own account. Contradictions between README and signals are surfaced for the owner to reconcile.
- **F36 Refusal.** `checkRequestPolicy` refuses requests to remove, hide, rewrite or obfuscate authorship signals, rewrite history to drop them, or pass a repo off as human-written, and explains why; legitimate requests (disclose, explain a flag, list signals) pass. The module has no write path at all: it reads files and commits and returns text.
- **F37 Fixtures and eval.** 9 self-authored fixtures in `fixtures/authorship/` (JSON rather than nested git repos, so tool files like `CLAUDE.md` do not exist as real files in this repository), generated by `scripts/build-authorship-fixtures.ts`, with `answer-key.json`. Precision/recall are computed over strong+moderate signals. False-positive rate = share of human-written fixtures where any strong/moderate AI-evidence signal fires or the status is not `none-found` (an unverifiable "hand-written" claim does not count). The gate also fails if an expected speculative signal does not fire. Like the bug benchmark this measures plumbing, not real-world accuracy.
- **F38 Fifth lane.** `authorship` is a member of `LaneSchema`. Each strong/moderate/speculative signal becomes a finding (label confirmed / likely / speculative; severity medium / low / low), plus one high-severity "Undisclosed…" or "Disclosure mismatch…" finding when the status needs action. Findings feed the judge, the evidence graph (tool files as file nodes, commit-based signals as a new `commit` node kind) and the handoff. Signals are never auto-patched (`generateCandidates` returns none) and the handoff tells the owner to disclose, not to remove.
- **F39 Seeded bug eval is scoped to the lanes in its answer key.** `scoreAgainstKey` ignores findings from lanes with no planted bugs (authorship), which has its own fixtures and eval. The seeded demo itself produces no authorship findings.
- **F40 Inputs per source.** Local path scans read the full file listing (hidden folders included) and `git log --numstat` (read-only; the module test asserts only `git log` is ever spawned and only read-only `fs` calls exist). GitHub scans use the tree listing and, from step 6, the commits API. README and `docs/*.md` are now fetched for GitHub scans so documentation claims can be checked.
- **F41 Interface.** MCP `assay_check_authorship` (seeded fixtures, local path, GitHub URL; optional `owner_tools`; optional free-text `request` that goes through the refusal policy) and `GET /api/authorship` (same policy, 422 on refusal). `assay_eval` also returns the authorship eval.
- **F42 Authorship view.** New "Authorship" entry in the Analyze group: disclosure status and overall result as text+icon badges, the summary with the "signals, not verdicts" note, strong/moderate/speculative counts plus what was looked at, signal cards (strength badge, kind, evidence, and a "False-positive caveat" box on speculative and history signals), and the disclosure draft with a copy button. "Fixture repos" mode (default) shows the authorship eval (precision, recall, false-positive rate on human-written fixtures, status accuracy) and a picker over the 9 fixtures; "Current scan" shows the active scan's report (local or GitHub).
- **F43 Live commit history.** `fetchCommits` (src/github/fetch.ts) reads commits through the same allowlisted client: a PR's own commits, or a repo's default-branch commits (≤200, 100 per page). List responses carry no line stats, so when the history is complete only the root commit is fetched in detail (one extra request) to support the large-initial-commit pattern; the burst pattern therefore cannot fire on live scans, and the report's coverage says "no line stats". A commit-history failure never fails the scan (the reason is added to the scan notes). Error messages are built from status/headers only (rate limit with reset time and the GITHUB_TOKEN hint, 401, 404 with a private-repo hint) so a token or query string cannot appear in them; tests assert this. Unauthenticated GitHub allows 60 requests/hour, and a scan makes one request per fetched file plus a few for the tree and history.
- **F44 Self-audit fixes.** Running the audit on Assay's own repo found two false positives in the detectors, both fixed with tests: (a) a README sentence describing what the tool reviews ("reviews AI-written code") was read as a disclosure; phrases that are the object of review/detect/scan/etc. are now skipped; (b) a capitalised component name (`function Bar`) matched the case-insensitive generic-names pattern; it is now case-sensitive. Style heuristics also skip test, fixture and e2e code, which quote placeholder text on purpose. `pnpm authorship [path] [--draft] [--json]` runs the audit on a local repository (tracked files via `git ls-files`, history via `git log`, both read-only).
- **F45 README acknowledgement.** The README ends with a one-line acknowledgement of the public project that inspired Assay. The forbidden-name test now allows the former project name in `README.md` only on a single line that starts with "Inspired by"; everywhere else (code, package name, fixtures, docs, commit messages) it stays forbidden. The link itself is left as a TODO comment because the project's URL was not provided; add it on that line.
- **F46 Second self-audit fix.** Documentation that *reports* a claim ("the README claims no AI use"), flags it, or gives an example of it ("pass as human-written", "a human-written fixture", "e.g. …"), and phrases like "no AI-tool trailers", are no longer read as the project's own statement. Genuine first-person statements still are ("This project is hand-written", "No AI was used", "Pair programmed with Claude Code"). This is phrase matching, so it can still misfire in either direction on unusual wording; the report always shows the matched lines.
- **F47 "How this was built" for Assay itself.** Generated with the disclosure helper from the self-audit plus a declaration (tool: Claude Code, used interactively; what it assisted), then edited. The declared statements are labelled as the owner's, not as detected; the two blanks about review and accountability are left for the owner to write.
- **F48 Live-scan rate-limit fix (found by the first real run).** A default-branch scan of a public repo without a token used all 60 of GitHub's hourly unauthenticated requests in about 23 seconds and then failed as a whole, discarding everything already fetched. Two causes, both fixed with tests: (a) the unauthenticated default of 80 files (one request each) could never fit in 60 requests; it is now 40 without a token (80 with one); (b) a rate-limit response while downloading files threw away the scan. Now `fetchGithub` keeps the files fetched so far, stops requesting (no retries), marks the scan truncated with `rateLimited: { resetAt, message }`, and lists the rest as skipped (rate limit); a limit hit before any file was fetched still fails with the clear message. Support files (manifests, README, specs) are downloaded before code. `scanGithub` now reads commit history first (a few requests) so the authorship audit keeps its data, and puts "partial scan: …" in the scan notes. The first-run result is recorded in the README.
